# 순위·장기 기준점·OCR 개선

2026-09-23. 작업 브랜치: `fix/ranking-retention-ocr`. 이 문서는 구현 내용이며 운영 배포 완료를 뜻하지 않는다.

## 사용자가 보게 되는 변경

- 사입 검토: 최근 30일 상위 50개 목록, 자료 확보 일수, 품목별 통계 참고/실사 권장 안내.
- 입고 등록: 상위 품목 여부 안내. 하위 품목 실사는 권장하되 입고 저장을 막지 않는다.
- OCR: 기기 안에서 표의 수량 열을 읽는다. 금액을 수량으로 추측하지 않는다. 사진을 보며 수정하고, 검색·신규 등록으로 상품을 연결할 수 있다. 미확정 행은 수정하거나 명시적으로 건너뛰어야 한다. 대조 확인 후 목록에 담는다. 원본 사진은 서버에 저장하지 않는다.
- 오래된 기준점: 180일 밖 판매량도 보존 누적분을 통해 차감한다. 이미 삭제된 자료로 기준점을 복원할 수 없으면 추천 보류 및 실사 안내.

## 보관 정책

회귀 학습은 최근 180일, 순위는 최근 30일이다. 재고 차감에는 기간 제한을 적용하지 않는다. 현재 실사/최근 입고 기준점별 삭제 구간 합계를 작은 별도 테이블에 보존한다. 전체 과거 일별 자료는 늘리지 않는다.

보관 중인 날짜의 재업로드는 반영된다. 이미 삭제한 구간은 차액을 알 수 없어 일반 재업로드를 거부한다. 삭제 구간에 새 과거 입고/실사를 입력하거나 기존 과거 기준점을 취소한 뒤 경계를 복원할 수 없는 경우 현재 실사로 복구한다. 일별 판매와 입고 시각의 차이는 기존 보수적 근사 규칙을 유지하며 실제 재고로 단정하지 않는다.

## 실제 제공 자료 확인

판매내역 원본 2026-08-23~2026-09-23: 기존 CatPOS 파서로 5,430개 상세 행, 오류 0건. 이 중 최근 30일(8월 25일~9월 23일)에 해당하는 상세 행은 5,023개다. 관측 이전 기간을 0으로 확장하지 않는다.

상품마스터의 중복 이름을 자동 병합하지 않으며 POS 재고를 실사 기준으로 자동 채택하지 않는다. 제공 파일은 운영 DB로 업로드하거나 저장소에 포함하지 않았다.

## 검증

- 타입검사·린트·단위 테스트·프런트 빌드.
- 임시 PostgreSQL에서 0001~0020 전체 적용 후 기존 업무 흐름 테스트.
- 251일 판매의 순차 이월(200일 보관→180일 보관), 반복 실행, 실사 다음날 차감, 0판매일, 보관 중 정정, 복원 불가 과거 기준점, 삭제 구간 재업로드 거부, RPC 권한.
- 55개 동률 품목에서 상위 50개 경계 및 안정적 순서, 30일 밖 판매 제외.
- OCR 금액 제외, 열별 OCR 블록 재결합, 수량 빈칸, 프로모션/낮은 신뢰도, 합계 제외, 분리된 헤더, 품명 생략 규격 행.

실제 iPhone 촬영 및 두 기기 UI 동시 사용 검수는 별도로 필요하다. 알고리즘 테스트 통과를 OCR 인식률 검증으로 대신하지 않는다.

## 운영 적용 순서

1. 다른 작업의 마이그레이션 번호와 충돌 여부를 확인한 뒤 0020 적용.
2. `forecast-batch` 배포. 새 RPC에 의존하므로 DB보다 먼저 배포하지 않는다.
3. 프런트 배포. 기존 RPC 인자는 변경하지 않아 전환 중 구버전 프런트와 호환된다.
4. 입고/실사가 있는 활성 품목만 `enqueue_recompute(product_id,false)`로 재계산한다. 운영 검증을 위해 가짜 발주·입고를 만들지 않는다.

GitHub Actions는 프런트만 배포한다. main 병합만으로 DB와 Edge Function이 적용된다고 생각하지 않는다. 배포 취소 시 DB 누적자료를 삭제하지 않고 프런트/Edge 코드를 이전 버전으로 복구하되 이전 Edge의 장기 기준점 한계에 유의한다.
