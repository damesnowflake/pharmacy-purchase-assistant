## Supabase 프로젝트 상태

마이그레이션 0001~0010이 모두 적용되어 있고, 공개 가입은 비활성화(FR-01), Auth 리디렉션은
위 Cloudflare Pages 주소로 설정되어 있다. Edge Function `holiday-sync`·`forecast-batch`도
배포되어 있다(정기 자동 호출은 아직 등록 안 함 — 아래 참고).

**마이그레이션을 다시 적용하거나 다른 프로젝트로 옮길 때:**

```bash
npx supabase login                      # 최초 1회, 브라우저 인증
npx supabase link --project-ref <ref>
npx supabase db push                    # 0001~0010 순서대로 적용
```

**추가 계정 발급** (FR-02, 화면에는 계정 발급 기능이 없다):

```bash
SUPABASE_URL=https://sotfjvjrtnnfgqsuxbgq.supabase.co \
SUPABASE_SERVICE_ROLE_KEY=...   # Supabase 대시보드 Project Settings → API에서 확인 \
npm run issue-account -- --email user@example.com --name "이름" --role staff
```

**Edge Function 재배포:**

```bash
npx supabase functions deploy holiday-sync
npx supabase functions deploy forecast-batch
npx supabase secrets set HOLIDAY_API_SERVICE_KEY=...   # 공공데이터포털 서비스 키 — 아직 미설정
```

**공휴일 API 키가 준비되면**, 위 secrets 설정 후 아래 SQL로 매일 자동 호출을 등록한다
(`pg_net` 필요, Supabase 프로젝트에는 기본 제공):

```sql
select cron.schedule('holiday-sync-0200-kst', '0 17 * * *', $$
  select net.http_post(
    url := 'https://sotfjvjrtnnfgqsuxbgq.supabase.co/functions/v1/holiday-sync',
    headers := jsonb_build_object('Authorization', 'Bearer <anon-or-service-key>')
  );
$$);
```

`forecast-batch`는 판매 업로드 직후 프론트에서 이미 자동 호출하므로(`SalesUploadPage.tsx`),
cron은 놓친 항목을 뒤늦게 처리하는 보조 수단으로 5~10분 간격 예약을 권장한다.
`0008_maintenance_and_capacity.sql`의 일일 유지보수(`daily-maintenance-0300-kst`)는 순수
SQL이라 `pg_net` 없이 이미 자동 등록되어 있다.

**설정(auth 등) 변경 시**: `supabase/config.toml`을 고친 뒤 반드시
`npx supabase config diff`로 실제 바뀌는 항목만 확인하고 `npx supabase config push --yes`로
반영한다 — `supabase init`이 만든 기본 템플릿에는 이 프로젝트와 무관한 값(MFA, Twilio, DB
풀러 크기 등)이 많이 들어 있어, 확인 없이 push하면 의도치 않게 바뀔 수 있다(실제로 겪음 —
아래 참고).

## 이번에 실제 연동하며 확인한 것 / 겪은 문제

- 마이그레이션 0001~0010을 실제 Supabase 프로젝트에 `db push`로 적용 → 오류 없음.
- **`auth.email.enable_signup=false`로 두면 공개 가입뿐 아니라 사전 발급 계정의 로그인 자체가
  막혔다** (CLI 문서의 "신규 가입 허용" 설명과 달리 실제로는 이메일 로그인 스위치였다). 다시
  `true`로 되돌리고 공개 가입 차단은 상위 `[auth] enable_signup=false` 하나로만 했다. 실제
  로그인 화면에서 성공을 확인했다.
- **`scripts/issue_account.ts`가 Node 20에서 즉시 실패**했다 — supabase-js가 내부적으로 만드는
  Realtime 클라이언트가 전역 WebSocket(Node 22부터 기본 제공)을 요구했다. `ws` 패키지를
  명시적으로 넘기도록 고쳤다.
- **`createClient('', '')`가 즉시 예외를 던져** Supabase 환경변수 없이 배포하면 앱 전체가 흰
  화면이 됐다 — "환경 설정 필요" 안내로 대체.
- 위 세 가지를 고친 뒤 판매 업로드(REST API, 180일 합성 데이터) → `forecast-batch` 호출 →
  추천 생성 → 발주 확정 → 부분 입고 → 전량 입고까지 실제 값으로 끝까지 확인했다(시험 자료는
  전부 삭제함). 자세한 수치는 [미확인_항목.md](미확인_항목.md)에 있다.
- 공휴일 API 키가 없어 `holiday-sync`는 배포·호출까지만 확인했고 실제 공휴일 데이터를 받아온
  적은 없다.
