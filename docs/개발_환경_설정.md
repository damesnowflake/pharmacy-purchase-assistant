# 개발 환경 설정

작성일 2026-09-23. 이 문서는 로컬에서 이 저장소를 실행·시험하는 방법을 정리한다. 실제 운영
계정·키 발급 방법은 이후 백엔드 개발 단계에서 별도로 문서화한다 (개발계획.md 참고).

## 프론트엔드만 띄우기 (Supabase 없이)

```bash
npm install
npm run dev
```

로그인 화면은 뜨지만 `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY`가 없으면 실제 로그인은 되지
않는다. `.env.example`을 복사해 `.env.local`을 만들고 실제 Supabase 프로젝트 값을 채운다.

## 순수 계산 로직 검증 (Supabase 불필요)

```bash
npm test          # vitest, src/lib/*.ts의 24개 단위 테스트
npm run typecheck
npm run lint
npm run build
```

## Supabase 프로젝트 연결 후

1. Supabase 프로젝트를 만들고 `SUPABASE_URL`, `anon` 키, `service_role` 키를 받는다.
2. `supabase/migrations/0001_*.sql`부터 `0006_*.sql`까지 순서대로 SQL 편집기 또는
   `supabase db push`(Supabase CLI)로 적용한다.
3. `.env.local`에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`를 채운다.
4. 최초 계정은 화면에서 만들 수 없다(FR-01~02). 셸에서 서비스 키로 발급한다.

```bash
SUPABASE_URL=https://xxxx.supabase.co \
SUPABASE_SERVICE_ROLE_KEY=... \
npm run issue-account -- --email admin@example.com --name "관리자" --role admin
```

5. Edge Functions(`supabase/functions/holiday-sync`, `forecast-batch`)는 Supabase CLI로
   배포하고, `HOLIDAY_API_SERVICE_KEY`를 프로젝트 시크릿으로 등록한다
   (`supabase secrets set HOLIDAY_API_SERVICE_KEY=...`). 두 함수 모두 아직 실제 배포·실행
   검증을 하지 못했다 — [미확인_항목.md](미확인_항목.md) 참고.

## 이번 환경에서 확인한 것 / 못한 것

- Supabase CLI(`supabase`), Docker가 이 개발 환경에는 설치되어 있지 않아 `supabase start`로
  로컬 스택을 띄워 보지는 못했다.
- 대신 로컬 PostgreSQL 16(Homebrew)에 `auth.users`/`auth.uid()`만 최소 스텁으로 채워
  6개 마이그레이션 전체를 적용하고 핵심 RPC(입고 등록, 발주 확정, 대기량 계산, 멱등성, 권한
  거부, RLS 조회 권한)를 실제 SQL로 실행해 검증했다. 자세한 내용과 남은 한계는
  [미확인_항목.md](미확인_항목.md)에 있다.
