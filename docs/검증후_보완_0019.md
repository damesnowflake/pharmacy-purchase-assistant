# 검증 후 보완 (0019)

- 정정 화면은 UTC 저장값을 KST로 표시한다. 시간 입력을 바꾸지 않은 수량 정정은 원본 시각(초·소수초 포함)을 그대로 전달한다.
- 실사 정정은 0 이상, 입고·발주·취소는 양수, 재고조정은 0이 아닌 수량으로 검증한다. 취소 RPC는 상품 잠금 안에서 현재 대기량을 초과한 취소를 거부한다.
- Realtime 변경을 이력·초과입고·상품·단위·거래처 등 관련 조회에 전파한다. publication도 같은 테이블로 확장한다. 연결 오류/시간초과 시 안내와 30초 조회 대체 동작을 제공하고, 재연결·앱 복귀 시 놓친 변경을 다시 조회한다.
- 계산 조건 부족은 queue `blocked`로 휴면 처리한다. 입고·실사·발주조건·판매자료·공휴일 변경 시 필요한 작업을 깨운다. 새 입력은 정기 작업보다 먼저 처리한다. 일시적 오류는 1분부터 최대 1시간까지 재시도 간격을 늘린다.
- 하루 변경은 계산 가능한 품목을 재예약하지만 기준점/설정이 없는 품목은 재예약하지 않는다. 판매 커버리지 증가로 학습 가능해지는 0판매 품목은 별도로 재예약한다.
- 화면에 입고/실사·MOQ·발주단위 미설정 개수를 함께 보여준다. 동일 품목이 여러 조건에 집계될 수 있다. 설정값을 임의 생성하지 않는다.

## 반영과 검증

새 마이그레이션 `0019_validation_findings.sql`을 먼저 적용하고 프런트엔드를 배포한다. 기존 RPC 인자와 Edge Function은 호환되므로 Edge Function 재배포는 필요하지 않다. 0001~0018을 수정하지 않는다. 기존 영업 기록을 수정하거나 삭제하지 않는다.

`npm run typecheck`, `npm run lint`, `npm test -- --no-cache`, `npm run build`, `bash scripts/test-review-db.sh`로 검증한다. DB 스크립트는 운영 DB와 분리된 임시 PostgreSQL만 사용한다. 0 실사 정정·초과 취소 거부·보류 큐 휴면/재개/우선순위/오류 지연과 이전 업무 흐름을 포함한다.

최초 보고된 브라우저 WebSocket 오류의 직접 원인은 재현되지 않았다. 이번 변경은 확인된 갱신 누락과 연결 실패 시 복구 경로를 보완한다. 특정 기기·네트워크에서 지속적으로 연결이 실패하면 그 환경의 로그로 별도 진단해야 한다.
