# Cloudflare Pages 자동배포

`main`에 push하면 GitHub Actions가 타입 검사·린트·테스트·빌드 후 Cloudflare Pages 프로덕션에 배포한다. Actions의 **Deploy to Cloudflare Pages → Run workflow**로 `main`을 수동 재배포할 수도 있다. 다른 브랜치는 프로덕션에 배포하지 않는다.

필요한 Actions repository secrets:

- `CLOUDFLARE_API_TOKEN`: 대상 계정의 Cloudflare Pages Edit 권한
- `CLOUDFLARE_ACCOUNT_ID`: 해당 계정 ID
- `VITE_SUPABASE_URL`: 프런트엔드용 Supabase 프로젝트 URL
- `VITE_SUPABASE_ANON_KEY`: 프런트엔드용 공개 키. service_role 키를 넣지 않는다.

시크릿 값은 코드·문서·로그에 기록하지 않는다. 토큰 만료/회수 시 같은 시크릿을 교체한다. 검사나 배포가 실패하면 GitHub Actions 로그에서 실패 단계를 확인한다. 동시 실행은 직렬 처리한다.

서비스: https://pharmacy-purchase-assistant.pages.dev

자동배포 범위는 **프런트엔드만**이다. Supabase DB 마이그레이션과 Edge Functions는 포함하지 않는다. 백엔드 계약이 바뀌는 변경은 백엔드를 호환 가능한 상태로 배포한 다음 `main`에 병합한다. 로컬에서 아직 push하지 않은 개발 변경은 자동으로 배포되지 않는다.
