# 코드리뷰 5건 수정

## 변경 내용

1. 발주 화면은 `p_expected_recommendation_version`을 전달한다. 버전 충돌 시 최신 추천을 조회하고 재확인을 요청한다.
2. 계산 큐 선점·완료·재예약과 내부 재계산 RPC는 `service_role`만 직접 호출한다. 활성 계정의 정상 업무 RPC는 기존 권한을 유지한다.
3. 공휴일은 올해·다음 해의 성공/정상 빈 결과 범위를 함께 확인한다. 조회 실패를 빈 데이터로 취급하지 않으며, 공휴일 부족은 `blocked/holiday_missing`으로 표시하고 재처리한다.
4. Edge Function은 `claim_recompute_batch`로 원자적으로 선점한다. 모델·참고량·추천 저장과 완료 처리는 새 `finish_recompute_item` 트랜잭션 한 번으로 수행한다. 토큰·리스 만료·입력 revision 중 하나라도 맞지 않으면 이전 계산을 저장하지 않는다. 새 revision은 대기 상태로 남긴다.
5. 입고 정정으로 미입고량이 다시 생기면 해당 미해소 구간의 발주 추천을 대기로 복원한다. 새 미발주 추천과 충돌하면 새 추천은 `not_needed` 이력으로 보존하고 실제 발주를 복원한다. 입고와 개별 발주를 연결하는 절차는 추가하지 않는다.

## 검증

- `npm run typecheck`, `npm run lint`, `npm run test -- --no-cache`, `npm run build`
- `bash scripts/test-review-db.sh`: 운영 DB에 접근하지 않는 임시 PostgreSQL. 전체 마이그레이션 적용, RPC 권한, 버전 충돌, 오래된 토큰·만료 리스·새 revision, 자료 부족 재처리, 입고 10→6 정정, 새 추천과의 충돌, 두 세션 동시 선점 검증.
- 다른 PostgreSQL 설치 경로는 `PG_BIN=/path/to/postgres/bin bash scripts/test-review-db.sh`로 지정한다.
- 테스트 종료 시 서버를 중지한다. `/tmp/ppa-review.*`의 로그와 임시 DB 파일은 디버깅을 위해 남긴다.

## 운영 반영 순서

이 변경은 로컬 검증과 운영 배포를 구분한다. 실제 배포 결과를 확인하기 전 운영 적용 완료로 보고하지 않는다.

1. 구형 계산기의 쓰기가 새 결과와 섞이지 않도록 정기 호출과 업로드 직후 계산 호출을 잠시 중지하고, 진행 중인 구형 계산이 종료됐는지 확인한다.
2. 새 마이그레이션 `0018_review_five_fixes.sql`을 적용한다. 기존 0001~0017을 수정하거나 DB를 초기화하지 않는다. 마이그레이션은 활성 품목을 재예약한다.
3. 새 `forecast-batch`를 배포한다. 신규 RPC 인자와 Edge Function은 반드시 함께 반영한다.
4. 프런트엔드를 빌드·배포하고 계산 호출을 재개한다. 정상 계정으로 발주 확정, 공휴일 범위, 추천 계산 상태를 확인한다.

외부에서 동시에 개발 중이라면 마이그레이션 번호와 수정 파일을 다시 확인한다. 같은 번호가 이미 사용됐다면 새 미적용 번호로 이동하며 적용된 파일은 변경하지 않는다.
