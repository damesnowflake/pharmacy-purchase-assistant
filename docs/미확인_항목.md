# 구현 중 미확인·차단 항목

작성일 2026-09-23. 이 문서는 코드 구현을 계속 진행하면서, 실제 계정·API 키·현장 표본이 있어야만
확정할 수 있는 항목을 모아 둔 목록이다. 아래 항목이 해결되지 않은 기능은 코드 상에서도
"완료"로 표시하지 않았다 (TODO 주석, 예외를 던지는 자리표시자 RPC, 비활성화된 UI 버튼 등).

## 1. 계정·서비스 필요

- **Supabase 프로젝트**: 아직 생성되지 않았다. 생성 후 `SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`,
  `SUPABASE_SERVICE_ROLE_KEY`를 받아야 `supabase/migrations`를 적용하고 프론트를 실제로 로그인
  테스트할 수 있다. 로컬 개발에는 Supabase CLI(`supabase start`, Docker 필요)도 필요하며 이번
  환경에는 설치되어 있지 않다 (`supabase not found`).
- **공휴일 API 키**: 공공데이터포털 "한국천문연구원 특일 정보"(`getHoliDeInfo`) 서비스 키가 없으면
  `supabase/functions/holiday-sync`를 실행할 수 없다. 엔드포인트·파라미터·응답 필드명은 공공데이터
  포털 문서로 확인했지만 실제 키로 한 번도 호출해 보지 않았다 (D-01과 무관, IR-09 참고).
- **Cloudflare Pages 프로젝트**: 개발계획.md가 GitHub Pages 대신 채택한 배포 대상이다. 계정 연결과
  빌드 설정(Actions 또는 Cloudflare 자체 빌드)은 아직 하지 않았다.

## 2. 실제 현장 자료 필요 (구현 순서 1단계)

- **D-02 CatPOS 판매 파일 실제 표본**: 열 구조, 반품·취소 표기 방식, 파일이 전체기간 보고서인지
  증분인지, 날짜·시각 형식을 확인해야 `src/features/sales`의 파서와 `begin_sales_import` /
  `commit_sales_import` RPC를 구현할 수 있다. 지금은 두 RPC 모두 `NOT_IMPLEMENTED` 예외를 던지고,
  프론트 판매 업로드 화면은 파일 선택까지만 동작한다.
- **D-04 iPhone 로컬 OCR**: 실기기에서 Tesseract.js 한국어 모델의 인식 품질·처리 시간·메모리를
  확인해야 한다. `src/features/receipts`의 "촬영으로 입력" 버튼은 비활성화된 채로 남겨 두었다.
  수동 입력(품목 검색 + 수량 입력) 경로는 완전히 동작한다.
- **입고장 사진 표본**: OCR 열 매핑(품명/규격/수량) 규칙을 검증하려면 실제 입고장 사진이 필요하다.

## 3. 설계상 확정되지 않은 계산 기본안 (D-01, D-03)

- **D-01 일 경계**: `src/lib/inventoryAnchor.ts`는 상세_알고리즘_설계.md의 초기 제안(최근 입고일
  전체 차감, 장중 실사는 당일 예측 전체 차감)을 그대로 구현했다. 실제 자료로 검증되지 않은
  기본안이라는 점이 코드 주석에도 남아 있다.
- **D-03 회귀모델**: 절편+선형추세+요일더미 8계수 OLS를 구현하고 24개 단위 테스트로 설계 문서의
  예제를 검증했지만, 실제 판매자료로 시간순 백테스트(WAPE/MAE)를 돌려 모델이 쓸 만한지 확인한
  적은 없다. `src/lib/regression.ts`의 `timeSeriesBacktest`는 함수만 준비되어 있다.

## 4. 코드 상 알려진 미완성/스캽폴드 (완료로 표시하지 않음)

- `supabase/functions/forecast-batch`: 최근 입고 기준(last-receipt anchor) 경로만 이식했다.
  실사 기준(stock-count anchor, 장중 보정 포함) 경로는 아직 옮기지 않았다. 이 함수는 실제
  Supabase 프로젝트에 배포해 실행해 본 적이 없다.
- `supabase/functions/holiday-sync`: 위 "공휴일 API 키" 항목 참고. 미배포·미실행.
- `supabase/migrations/0005_permissions_rpc.sql`의 `begin_sales_import`, `commit_sales_import`:
  호출 시 `NOT_IMPLEMENTED` 예외를 던지는 자리표시자.
- 거래처 조건(`purchase_terms`)·휴무일(`supplier_closed_dates`) 편집 화면: DB·RPC는 있지만
  `src/features/settings`에는 아직 화면을 연결하지 않았다 (품목 MOQ/발주 단위만 연결함).
- RLS·RPC를 실제 Supabase 프로젝트(Auth·PostgREST·Realtime 포함)에 적용해 본 적은 없다. 로컬
  임시 PostgreSQL로 검증한 범위와 한계는 아래 "5. 확인된 사항"을 참고한다. 동시성(잠금 경합)·
  Realtime·실제 JWT 클레임 형식·트리거 간 상호작용은 여전히 검증하지 못했다.
- 계정 발급 스크립트(`scripts/issue_account.ts`)는 실제 서비스 키로 실행해 본 적이 없다.

## 5. 확인된 사항 (검증 완료, 완료로 표시 가능)

- 핵심 순수 계산 로직(`src/lib/*.ts`)은 개발계획.md·상세_알고리즘_설계.md의 모든 숫자 예제를
  vitest 24개 테스트로 재현했다: 도착일 계산(토요일→화요일, 월요일 휴일→수요일), 추천 수량
  (MOQ 10·7일수요 23·단위 6→24), 발주-입고 대기량 사건 표 전체, 참고값 예제(입고100-판매80-
  예측20=0), 회귀모델의 불충분/rank 부족/음수예측 클램프/불완전 창 경고.
- 프론트엔드는 `npm run build`로 정상 빌드되고, 로그인 화면이 데스크톱·375px 모바일 뷰포트
  모두에서 콘솔 오류 없이 렌더링됨을 브라우저로 확인했다. (실제 Supabase 미연결 상태이므로
  로그인 성공 여부, 이후 화면들의 실제 데이터 연동은 아직 확인하지 못했다.)
- DB 마이그레이션 6개(`supabase/migrations/0001~0006`)는 로컬 임시 PostgreSQL 16 인스턴스에
  `auth.users`/`auth.uid()`/anon·authenticated 역할만 최소 스텁으로 채워 처음부터 순서대로
  적용했다. 전체가 오류 없이 적용되었고, 다음 시나리오를 실제 SQL 실행으로 확인했다: 비활성
  계정의 RPC 거부, 박스→기준단위 환산(2박스→20개), 같은 request_id 재시도 멱등성과 다른 내용
  재시도 시 REQUEST_CONFLICT, 직원의 confirm_order 호출 거부(FORBIDDEN_ADMIN_ONLY), 발주10→
  입고6→입고4 사건에서 대기량이 설계 문서 표와 동일하게 10→4→0으로 변화, save_product_settings의
  VERSION_CONFLICT, RLS 조회 권한(활성 계정만 조회, 비활성 계정은 0건, anon은 permission denied).
  이 과정에서 실제 버그를 하나 발견해 고쳤다: RLS 정책만 있고 `authenticated` 역할에 테이블
  SELECT GRANT가 없어 모든 조회가 permission denied로 실패했던 문제
  (`0005_permissions_rpc.sql`에 GRANT SELECT 블록을 추가해 수정).
