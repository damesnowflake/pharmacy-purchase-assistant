# 예측 경고와 오차 평가

## 사입 검토 화면

`예측 품질·음수 경고 보기`에서 상품 검색, 음수 예측 품목 필터, 평가 결과를 조회한다. 추천이 없거나 입고·MOQ가 없어 계산이 보류된 품목도 학습 가능한 자료가 있으면 결과를 볼 수 있다. 직원과 관리자 모두 조회 가능하다.

음수 예측은 날짜·보정 전 원값·적용값 0을 저장한다. 추천 계산은 기존대로 0을 사용하고 발주를 추가 차단하지 않는다. 모델과 발주 검토 근거에 경고를 함께 남긴다. 도착일부터 7일분까지의 운영 예측 구간을 확인하고, 공휴일 자료가 없어 도착일을 못 정하면 다음 14일을 진단한다. 장중 실사 보정에 음수 예측이 사용되면 그 날짜도 기록한다.

## 평가 방식

학습 창은 최대 180일이며 그 안의 마지막 28개 달력일을 날짜별로 평가한다. 각 평가일 이전 관측만으로 다시 학습하여 해당 날짜의 예측과 실제 순판매량을 비교한다. 자료 없는 날을 0으로 보충하지 않는다. 8개 계수를 식별할 수 없으면 그 날짜는 평가하지 않는다.

- MAE: 평가일의 절대오차 평균. 단위는 해당 상품 기준단위.
- WAPE: 절대오차 합 / 실제 순판매량 절대값 합. 분모 0이면 N/A.
- 단순 평균: 동일한 과거 관측의 평균과 비교하는 참고 지표다. 운영 예측식으로 대체하지 않는다.
- 평가 일수 / 28일을 함께 표시한다. 28일 미만이면 부분 평가, 한 날짜도 평가할 수 없으면 자료 부족이다.

이 수치는 과거 자료 재검증이며 운영 당시 미리 저장한 예측과 한 달 뒤 실적을 비교한 결과는 아니다. 미래 정확도 보증이나 임의의 합격률을 표시하지 않는다. 순판매 반품·취소 형식이 달라지면 원자료부터 확인한다.

## 저장과 갱신

0021에서 `forecast_models`에 `negative_forecasts`, `evaluation`, 진단 기간을 추가한다. 기존 MAE/WAPE 열도 실제로 채운다. 품목당 최신 결과만 저장하며 매일 전체 예측 이력을 쌓지 않는다. 발주 근거의 당시 요약은 유지한다.

기존 `finish_recompute_item`의 잠금·리스·자료 버전 검증을 그대로 사용하며 같은 트랜잭션으로 경고·평가를 저장한다. 오래된 계산은 결과를 덮어쓰지 못한다. 파일 교체 후 모델이 더 이상 학습되지 않으면 이전 모델과 평가 캐시를 제거한다. 조회 화면은 자료 버전·학습 종료일이 오래되면 이전 자료 기준임을 표시한다.

판매 업로드 등 기존 재계산 경로에서 평가도 함께 갱신한다. 입력 전제조건이 없는 품목은 기존처럼 대기하며 무조건 반복 계산하지 않는다. 초기 배포에서는 기존 활성 품목을 한 번 재계산 대기열에 넣고 판매량 높은 품목부터 처리한다. 아직 처리되지 않은 품목은 평가 전으로 표시한다.

DB 0021 → forecast-batch → 프런트 순서로 배포한다. 프런트의 GitHub Actions만으로 DB/함수가 적용되지는 않는다.

## 1개월 이상 운영 후 개선

실제 기기 검수는 배포의 선행 조건이 아니다. 실제 운영 시작일부터 1개월 이상 사용하면서 다음 사항을 간단히 기록한다.

- 날짜·기기·화면과 불편하거나 잘못된 동작
- OCR 상품/수량 수정 사례, 상품 연결 문제
- 담당자가 추천수량을 수정한 이유, 품절·과잉 사입 사례
- 파일 업로드·로그인·다기기 갱신 문제

사진 원본의 서버 보관 정책은 변경하지 않는다. 수집한 사례와 당시 계산 근거를 함께 검토해 다음 개선을 정한다. 업무 중단이나 데이터 오류는 한 달을 기다리지 않고 처리한다. 별도 반복 알림이나 자동 감시 작업은 생성하지 않는다.
