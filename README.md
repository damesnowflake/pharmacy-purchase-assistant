# 약국 사입 추천 시스템

직원이 판매·입고 자료를 등록하면 시스템이 사입 검토안을 만들고, 관리자가 확인해 직접 발주하는 웹 서비스입니다. 현재는 문서 단계이며 서비스 기능은 아직 구현되지 않았습니다.

**현재 개발 기준:** [사입 추천 시스템 개발 작업지시서](docs/사입추천시스템_개발작업지시서.md)

## 업무 흐름

1. 직원이 Windows 11의 CatPOS Cloud(팜페이) PC에서 판매내역을 하루 한 번 내보내 업로드합니다. 시스템은 품목별·일자별 판매수량으로 집계합니다.
2. 직원이 iPhone에서 종이 입고장을 촬영·OCR하고 품목과 실제 입고 수량만 확인해 등록합니다. 사진은 서버에 보관하지 않습니다.
3. 시스템이 최근 180일 판매 추세, 재고 참고값, 공휴일을 제외한 2영업일 도착일을 이용해 사입 검토안을 만듭니다.
4. 관리자가 Windows 또는 macOS에서 추천을 검토·수정하고, 실제 발주 후 완료 표시합니다.
5. 이후 입고를 등록하면 품목별 발주량 대비 입고량을 확인하고 진행 중 목록을 갱신합니다.

사전 발급 계정만 로그인할 수 있으며 계정은 지정된 마스터 계정 보유자 또는 백엔드 개발자가 직접 발급합니다. 서비스 사용 권한은 관리자와 직원 두 종류이고, 관리자가 발주 담당자를 겸합니다. 다섯 명 안팎의 사용자가 같은 최신 자료를 볼 수 있도록 웹 표준을 따르는 반응형 서비스로 개발합니다.

## 배포·운영 방침

프론트엔드는 GitHub Pages, 로그인·DB·서버 작업은 Supabase 무료 플랜을 사용합니다. 별도 DB 백업 없이 운영하며, 장애 시 수동 발주로 전환하고 가능한 범위에서 복구를 시도합니다. 데이터 복구는 보장되지 않습니다. Supabase 프로젝트 일시정지·재개 절차는 백엔드 구현 시 문서화합니다.

## 요구사항과 디자인

[소프트웨어 요구사항 명세서](docs/소프트웨어_요구사항_명세서.md)에 기능적·비기능적·인터페이스 요구사항과 검수 기준을 정리했습니다. 관리자 PC는 실시간 표와 키보드 조작 중심의 업무용 터미널, 직원 iPhone은 촬영·품목·수량 입력 중심으로 구성합니다. 제공된 Bloomberg Terminal Clone README의 디자인 철학을 참고하며 기술 스택이나 금융 기능을 그대로 채택하지 않습니다.

## 개발 계획과 설계

[개발 계획](docs/개발계획.md)에 구현 순서·검증 기준·예상 작업량을 정리했습니다. 기술 구조는 [시스템 구조](docs/시스템_구조_설계.md), 테이블·권한·보관은 [DB 설계](docs/데이터베이스_설계.md), 수요 회귀·배송일·추천량·입고 대기량은 [상세 알고리즘](docs/상세_알고리즘_설계.md)을 따릅니다. 회귀식과 장중 실사 보정은 실제 자료로 검증할 설계 기본안입니다.

GitHub Pages의 로그인·상거래 관련 사용 제한은 운영 배포 전에 확인해야 합니다. 자세한 근거와 적용 범위는 개발 계획에 기록했습니다.
