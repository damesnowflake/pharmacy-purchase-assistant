# 약국 사입 추천 시스템

직원이 수집한 판매내역·입고장·실사 자료를 바탕으로, 발주 담당자가 근거를 확인하고 최종 구매를 결정하도록 지원하는 웹 서비스의 신규 프로젝트입니다.

개발 기준: [사입 추천 시스템 개발 사양서 v1.0](docs/사입_추천_시스템_개발_사양서_v1.0.md)

## 프로젝트 상태

현재는 개발 사양과 업무 경계를 확정하기 위한 문서 단계입니다. 로그인, 판매파일 업로드, 입고장 판독, 재고 원장, 추천 계산, 발주 화면은 아직 구현되지 않았습니다. 실제 판매내역과 입고장 원본은 이 저장소에 포함하지 않습니다.

기존 공개 저장소 [`hobumleo-del/-`](https://github.com/hobumleo-del/-)에는 수동 입력과 브라우저 `localStorage`를 사용하는 단일 페이지 주문 최적화 프로토타입이 있습니다. 이 신규 프로젝트는 해당 저장소의 포크가 아니며, 코드를 자동으로 가져오지 않습니다. 향후 재사용 가능 범위는 [병합 가능성 검토](docs/기존_프로토타입_병합_검토.md)를 참조하세요.

## 목표 업무 흐름

1. 직원이 Windows 11 POS PC에서 하루 1회 판매내역을 내보내고 웹 서비스에 업로드합니다.
2. 직원이 배송 때마다 iPhone으로 종이 입고장을 촬영하고 실제 입고량을 확인합니다. 필요한 품목은 전체 재고도 실사합니다.
3. 시스템이 최근 30일 판매 순위와 품목별 일별 판매 추세를 분석하고, 확정 입고·실사·미입고 주문을 연결해 사입 검토 신호와 구매안을 계산합니다.
4. 국장이 Windows 또는 macOS 브라우저에서 추천 근거, 배송일정, MOQ, 도매상 최소금액, 프로모션을 검토합니다.
5. 국장이 기존 도매상 주문 채널에서 주문하고, 실제 주문·부분입고 상태를 시스템에 기록합니다.

사용자는 사전 발급된 개인 계정으로 로그인합니다. 모든 기기는 중앙 서버의 동일한 자료를 사용하며, 저장·확정된 변경사항을 접속 중인 화면에 공유합니다. POS에서 아직 내보내지 않은 판매자료는 서비스에 자동 반영되지 않습니다.

## 사입 정책 요약

- 최근 30일 판매수량 상위 50개 품목은 통계 중심으로 관리하고, 나머지는 입고 시 실사와 필요 시 재확인을 중심으로 관리합니다.
- 현재 POS 전산 재고값은 필수 입력이 아닙니다. 실사 기준이 없을 때는 마지막 확정 입고량과 이후 판매량으로 발주 검토 신호를 제시하되, 정확한 전체 재고라고 표시하지 않습니다.
- 일별 판매량은 가능한 90~180일 이력의 추세·요일 효과를 분석해 예측하고, 검증에서 단순평균보다 나쁘거나 이력이 부족하면 기준모형을 사용합니다. 최근 30일은 상위 50개 순위의 기준으로 유지합니다.
- 기본 발주 검토 시점은 향후 약 2일 예상 판매분입니다. 주말·공휴일과 공급사 업무일·배송일을 반영합니다.
- 구매수량은 MOQ와 발주단위를 만족하는 최소안을 기본으로 제시하고, 7일 판매분 구매안을 비교합니다.
- 도매상별 최소주문금액이 우선하며, 초기 기본값은 의약외품 5만 원, 의약품 20만 원입니다.
- 추천과 최종 주문은 구분됩니다. 담당자가 실제 주문을 기록한 뒤에만 미입고 주문으로 계산합니다.

정확한 계산식, 데이터 누락·정정 처리, 화면·권한·검수 기준은 [개발 사양서](docs/사입_추천_시스템_개발_사양서_v1.0.md)를 따릅니다.

## 개발 순서

| 단계 | 결과 |
|---|---|
| 입력 규격 확인 | 실제 POS 출력 형식, 거래·상품 식별자, 공급사 정책 확인 |
| 공통 기반 | 계정·권한, 중앙 저장, 업로드, 기기 간 상태 공유 |
| 업무자료 반영 | 판매파일 해석, 입고장 판독·검수, 상품 매칭, 실사·재고 원장 |
| 추천·발주 | 30일 순위, 일별 수요예측, 최근 입고분 소진 신호, 배송 달력, 구매안, 최소금액·프로모션, 발주·부분입고 |
| 운영 검수 | 실제 Windows·Mac·iPhone과 현장 표본으로 검수 |

구현이 시작되면 실제 실행방법, 환경변수, 배포·백업 절차를 이 README에 추가합니다.

## 자료 취급

실제 판매내역, 입고장 사진, 거래처 가격표, 계정정보를 Git 저장소에 커밋하지 않습니다. 개발·검수 자료는 개인정보와 사업자 정보가 제거된 표본으로 관리합니다.
